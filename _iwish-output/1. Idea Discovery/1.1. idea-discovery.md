# Idea Discovery: UI/UX OS (FlowForge)

## 1. Executive Summary & Core Value
- **Core Value Proposition**: Chuyển hóa toàn bộ quy trình thiết kế giao diện ứng dụng và xây dựng bài trình chiếu/báo cáo doanh nghiệp từ các file tĩnh rời rạc thành một **Harness OS có cấu trúc, chạy bằng HTML sống**, giúp AI Agent và người dùng phi kỹ thuật phối hợp chỉnh sửa, nghiệm thu và xuất bản mà không bao giờ bị lệch chuẩn thương hiệu (zero design drift).
- **Target Personas**:
  1. *Non-tech Founder / Business Leader / Marketer*: Cần tạo slide trình chiếu, báo cáo KPI, landing page HTML nhanh chóng, muốn chỉnh sửa câu chữ (wording), số liệu trực tiếp qua khung CMS dễ như gõ tin nhắn mà không phải đọc code.
  2. *AI Agent & Vibe Coder*: Cần môi trường thực định (Harness) có ranh giới rõ ràng, không bị tràn token, có thể đọc hiểu AST, sửa đổi số liệu và chạy kiểm thử tự động.
  3. *Enterprise Product Team*: Cần quản lý bối cảnh đa dự án (Superadmin, Tenant Admin, Sales App) dùng chung một hệ thống Brand Token và Iconography duy nhất.
- **The Core Problem**: Sự đứt gãy giữa các công cụ thiết kế/trình chiếu truyền thống (PPTX, Google Slides, Figma tĩnh) với AI Coding Agents. Slide nhị phân (.pptx) khiến Agent bị mù, dễ làm hỏng file (XML corrupt), trong khi các công cụ prompt-to-code hiện tại nhồi nhét tài liệu gây tràn context và ảo giác mã màu/layout.

## 2. Phân tích 5 Lăng Kính (The 5 Lenses of Discovery)

### 🔍 Lens 1: Customer & Context
- **Nỗi đau 1 (Non-tech User):** Muốn sửa 1 con số doanh thu hoặc câu văn trên slide phải mở PowerPoint hoặc nhờ dev sửa code; slide gửi đi thì mỗi phòng ban dùng một font chữ, màu sắc lộn xộn.
- **Nỗi đau 2 (AI Engineering Team):** Khi giao Agent viết giao diện hoặc cập nhật báo cáo, Agent tự tiện dùng Tailwind, tự bịa mã hex `#3b82f6`, tự import icon từ các thư viện lạ, phá nát Brand Identity của công ty.
- **Nỗi đau 3 (Chi phí & Token):** Nhồi 50 trang PRD và hàng chục nghìn dòng CSS vào prompt khiến chi phí token tăng vọt và Agent bị "ngộ độc bối cảnh" (Lost in the Middle).

### 🎯 Lens 2: Problem & Value Proposition
- **Nguyên nhân Gốc rễ:** Bắt LLM làm việc của phần mềm thực định (tự căn chỉnh tọa độ, tự nhớ mã màu) thay vì cung cấp một **Agent Harness** để đóng khung ranh giới.
- **Tuyên ngôn Giá trị:** *"Một giao diện Dual-Pane thống nhất: Khung trái là CMS/Chat cho con người điều khiển ý đồ, Khung phải là HTML tương tác cho Agent điều phối; được bảo vệ bởi Spec Registry và Zero-Tailwind Token Contract."*

### 🛡️ Lens 3: Competitors & Moat
- **Đối thủ Truyền thống:** PowerPoint, Google Slides, Pitch, Gamma (Không thân thiện với AI Agent, định dạng đóng/nhị phân, không thể version control bằng Git).
- **Đối thủ AI Prompt-to-Code:** v0.dev, Lovable.dev, Bolt.new (Chỉ tập trung vào tạo trang đơn lẻ, thiếu State Machine đa màn hình, không giải quyết bài toán slide/report doanh nghiệp, phụ thuộc nặng vào Tailwind).
- **Moat Phòng vệ:**
  1. *Spec Registry & JIT Prompt Assembly:* Tiết kiệm 80% token so với đối thủ.
  2. *Dual-Pane CMS + HTML Presentation:* Cầu nối duy nhất cho non-tech user và AI cùng làm việc trên 1 file HTML sống.
  3. *Zero-Trust Category A Harness:* Tích hợp sâu vào Cowok.ai qua giao thức MCP, tự động test bằng Playwright trước khi render.

### 🛠️ Lens 4: Execution & MVP Scope
- **Phạm vi Tuần 1 (Week-1 MVP):**
  1. Khởi tạo Spec Registry đọc bộ token CSS thuần (`tokens.css`) và 145 icon từ `cowok-brand-product-system-v4.3`.
  2. Giao diện Dual-Pane Presentation: Sửa text khung trái $\to$ cập nhật slide HTML 16:9 khung phải (< 300ms).
  3. Máy trạng thái XYFlow Canvas cho luồng ứng dụng đa màn hình.
  4. MCP Server cung cấp 6 công cụ cốt lõi cho Cowok.ai.
- **Rủi ro Thất bại Lớn nhất:** Lệch pha giữa mã nguồn sửa tay và Spec Registry. (Giải pháp: Reverse AST Scanner).

### 📈 Lens 5: Metrics & Growth
- **North Star Metric:** *Time to Accepted Executable Artifact* (Thời gian từ lúc nạp ý đồ đến khi xuất bản thành công slide hoặc màn hình hoàn chỉnh đạt chuẩn).
- **Secondary Metrics:** Tỷ lệ tiết kiệm token (Token Efficiency >= 75%), Tỷ lệ vượt qua kiểm định Playwright vòng 1 (First-pass Acceptance >= 90%), Độ tuân thủ Token Contract (100% Zero Hex Codes).
