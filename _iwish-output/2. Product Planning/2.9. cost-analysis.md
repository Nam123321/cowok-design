# 2.9. Cost Analysis & FinOps Token Economics — UI/UX OS (FlowForge)

## 1. Mô hình Kinh tế Kép: BYOS (\$0 Marginal Cost) vs. BYOK (Pay-per-Token)

**UI/UX OS** được thiết kế từ đầu để tối ưu hóa chi phí vận hành AI thông qua 3 trụ cột:
1. **BYOS (Bring Your Own Subscription):** Tận dụng hạn mức thuê bao sẵn có của người dùng trên terminal (`Claude Pro/Max` qua `claude` CLI, `ChatGPT Plus/Pro` qua `codex` CLI, `Gemini Advanced` qua `agy`, hoặc mô hình nội bộ qua `ollama`) $\to$ **Chi phí biên (Marginal API Cost) bằng \$0.00**.
2. **JIT Context Slicing (`crates/prompt-assembler`):** Cắt giảm **82% – 88% lượng token đầu vào** so với cách nạp nguyên cả file `DESIGN.md` và mã nguồn toàn dự án.
3. **Deterministic AST Patching (`crates/ast-guardian` + Dual-Pane CMS):** Mọi thao tác sửa chữ, đổi số liệu báo cáo, đổi biến màu hoặc thay icon trong Dual-Pane CMS được thực hiện trực tiếp trên cây AST trong **<1ms với 0 token LLM**.

---

## 2. Phương trình Ngân sách Token (Token Budget Governor Math)

Với mỗi yêu cầu gửi tới LLM (dù qua BYOS hay BYOK), `crates/prompt-assembler` áp dụng công thức kiểm soát cứng:

$$B_{\text{total}} = T_{\text{system}} + T_{\text{spec\_slice}} + T_{\text{portal\_slice}} + T_{\text{user\_intent}} + T_{\text{output}} \le 4,000 \text{ tokens}$$

Trong đó ngân sách đầu vào ($T_{\text{input}}$) bị khóa chặt ở ngưỡng:

$$T_{\text{input}} = T_{\text{system}} + T_{\text{spec\_slice}} + T_{\text{portal\_slice}} + T_{\text{user\_intent}} \le 1,500 \text{ tokens}$$

### Bảng Phân bổ Ngân sách Token theo Loại Tác vụ (Task Horizon)

| Loại Tác vụ (Task Horizon) | Ví dụ Nghiệp vụ | $T_{\text{input}}$ (Classic Naive Agent) | $T_{\text{input}}$ (UI/UX OS JIT Slicer) | Mức Tiết kiệm Token | Chi phí BYOS | Chi phí BYOK ước tính (Claude 3.7 Sonnet / GPT-4.1) |
| :--- | :--- | :---: | :---: | :---: | :---: | :---: |

| **T1: Short-Horizon (Micro Co-Pilot)** | Yêu cầu Agent viết lại 1 đoạn bullet trên slide 16:9 cho súc tích hơn | ~12,000 tokens | **450 – 750 tokens** | **~94%** | **\$0.00** | **~\$0.0025 / lần** |

## 3. So sánh Chi phí Hạ tầng Máy chủ & Tài nguyên Máy trạm (Rust Day-1 vs. Node.js/Electron)

Việc triển khai **Rust Core Daemon (`crates/harness-daemon`) ngay từ Ngày 1** mang lại lợi thế vượt trội về chi phí tài nguyên phần cứng khi chạy song song cùng **Cowok.ai**:

| Chỉ số Tài nguyên | Kiến trúc Node.js + Babel/ESLint Truyền thống | Kiến trúc Day-1 Rust (`Axum` + `oxc` + `rusqlite`) | Hiệu quả Tối ưu |
| :--- | :---: | :---: | :--- |
| **RAM chiếm dụng khi chạy nền (Idle RSS)** | ~280 MB – 450 MB | **18 MB – 32 MB** | Giảm **~90% RAM** |
| **Thời gian khởi động (Cold Start)** | ~1,200 ms – 2,500 ms | **< 15 ms** | Nhanh gấp **~100 lần** |
| **Độ trễ quét Linter & Patch `data-ff-id`** | ~85 ms – 220 ms (Babel/ESLint) | **0.4 ms – 0.9 ms** (`oxc` AST) | Nhanh gấp **~200 lần** |
| **Chi phí Database ngoài (Cloud DB)** | \$25 – \$100/tháng (Managed Postgres) | **\$0.00** (Embedded `rusqlite` WAL local-first) | Tiết kiệm **100% chi phí DB** |
