# Phase 3 — Synthesis, Polish & Craft Execution

## Objective
Assemble production-grade application screens (`app-fe-be`) or executive adaptive slide decks (`presentation-16-9`, `16:10`, or `Auto`) using Phase 2 semantic CSS variables, registered catalog components, data storytelling patterns, and responsive accessibility craft.

## Operating Procedure
1. **Dynamic `tokens.css` Binding:** Resolve and bind every color, surface, border, and elevation strictly to the active project `tokens.css` semantic variables (`var(--bg-workspace)`, `var(--bg-surface)`, `var(--bg-elevated)`, `var(--border-default)`, `var(--text-primary)`, `var(--text-secondary)`, `var(--action-primary)`) — zero raw hex leaks, zero mismatched non-canonical token names, and zero Tailwind `dark:` utilities.
2. **Compose Domain & Craft Specialists:** Pair with `data-viz-storyteller` for insight-led charts/dashboards, `dashboard-ux` / `stageshow-slide` / `impeccable-polish` for craft execution, and `responsive-and-a11y-craft` for fluid viewport & keyboard resilience.
3. **Surgical Patch Discipline:** For targeted refinements (`MICRO_POLISH` or iterative edits), invoke `de-patch-dom` against stable `data-ff-id` / `data-ff-role` anchors so untouched regions stay byte-stable.
4. **Disjoint Scope Containment:** Keep every parallel writer confined strictly to its assigned disjoint `write_scope`.
