# Competitive Strategy, ICP, Business Moat & GTM

## Category and wedge
**Category hypothesis:** Executable UX Design Workspace / Flow-first Code-native Product Design.  
**Wedge:** non-tech product owners + vibe coders building multi-step B2B web apps.  
**Positioning:** “Design the experience, not just the screens.”  
**Promise:** articulate intent → verify user journey in a running preview → ship reviewable real code.

## What NOT to use as sole USP
“AI generates UI”, MCP, BYO provider, export React/HTML, live preview and visual style editing have observable competitive overlap. They can be necessary but are not durable differentiation alone.

## Four compounding advantages (hypotheses)
1. **Flow Intelligence:** versioned model of screen-state + conditions + action semantics; measurable coverage and regression test generation.
2. **Intent Intelligence:** intent schemas, visual disambiguation, human decision provenance, high-signal UX patterns; reduce rework through data and evaluation.
3. **Execution Reliability:** predictable AST edits, state fixture adapters, browser validation and minimal diffs; trusted code handoff.
4. **Decision Graph:** requirements → alternatives → approvals → flow states → code patches → validations; enables later changes with impact awareness.

These are *potential* moats, not established defensive barriers. Competitors can copy features; sustainable advantage needs data, workflow adoption, reliability, integrations and distribution.

## Go-to-market hypothesis
- Initial cohort: 20–30 founder/PO/vibe-coder teams building internal B2B SaaS/dashboards.
- Offer guided trial: “describe a B2B workflow; get working 8-state flow + exported repo”.
- Distribution: case studies with before/after rework reductions, workflow templates (approval, onboarding, inventory), developer communities, GitHub starter repos, product owner networks.
- Land via one project/flow, expand through review and decisions shared with collaborators.
- Pricing experiments: freemium projects + seat-based collaboration + usage-based model/sandbox credit; BYO API may reduce LLM expense but platform still bears orchestration/compute/storage costs.

## Competitive comparison test
Benchmark Onlook, pen.dev, Figma Make (respect beta access), v0 and our prototype against identical, anonymized 9-state order approval scenario. No unsupported “competitor lacks X” claims. Capture screenshots, output code quality, duration, model and plan/version.

## Moat scorecard to establish empirically
- 30%+ reduction in median accepted-flow time vs baseline (target hypothesis).
- 20%+ relative first-pass acceptance improvement (target hypothesis).
- >=95% clean exported builds on supported template (engineering gate).
- >=90% element anchor recovery within constrained template (engineering gate).
- Lower cost per accepted change (must report, no invented reduction).

## Strategic risks / response
- Incumbent catches up → deepen workflow + decision graph rather than chase UI generator features.
- Users hate question overload → only clarify at high uncertainty or risk; track skip rate.
- Harness costly → limit revision loops, deterministic tools first, caching and cheap model routing.
- Repo compatibility impossible → stay constrained, clearly label supported stacks and add adapters gradually.
- Trust concerns → visibility of diff/test, reversible changes, strong isolation and clear data policy.

## Defensibility proof
Do not call product a category winner until external users repeatedly complete realistic multi-state projects faster with fewer acceptance revisions than alternatives and successfully ship exported code.
